# Documentation Templates

C_capture 프로젝트의 일관된 문서화를 위한 표준 템플릿 모음

## 📁 템플릿 구성

### 기술 문서 템플릿
- **technical-analysis-template.md** - 기술 분석 보고서 표준 형식
- **optimization-proposal-template.md** - 성능 최적화 제안서 형식
- **api-documentation-template.md** - API 문서화 표준
- **troubleshooting-guide-template.md** - 문제 해결 가이드 형식

### 프로젝트 관리 템플릿
- **adr-template.md** - Architecture Decision Record 형식
- **release-notes-template.md** - 릴리즈 노트 표준
- **meeting-notes-template.md** - 회의록 표준 형식
- **progress-report-template.md** - 진행 상황 보고서

### 사용자 가이드 템플릿
- **user-manual-template.md** - 사용자 매뉴얼 구조
- **installation-guide-template.md** - 설치 가이드 표준
- **quickstart-template.md** - 빠른 시작 가이드
- **faq-template.md** - 자주 묻는 질문 형식

## 🎯 문서화 원칙

### 구조 일관성
- **YAML 메타데이터** 포함 (제목, 작성자, 날짜, 버전)
- **목차 (TOC)** 자동 생성 지원
- **명확한 섹션 구분** (H1~H6 적절한 활용)
- **시각적 요소** 활용 (이모지, 표, 코드 블록)

### 내용 품질
- **실행 가능한 코드 예제** 포함
- **스크린샷 및 다이어그램** 적절히 활용
- **상호 참조 링크** 체계적 연결
- **검색 키워드** 최적화

## 🚀 템플릿 사용법

### 새 문서 생성 과정
1. 적절한 템플릿 선택 및 복사
2. 메타데이터 섹션 작성
3. 템플릿 가이드라인을 따라 내용 작성
4. 관련 문서와의 링크 연결
5. 리뷰 및 피드백 반영

### 일관성 체크리스트
- [ ] YAML 메타데이터 완성
- [ ] 한국어 맞춤법 검사
- [ ] 기술 용어 일관성 확인
- [ ] 코드 예제 실행 가능성 검증
- [ ] 외부 링크 유효성 확인

## 📊 문서 품질 메트릭

### 평가 기준
- **가독성**: 비개발자도 이해 가능한 명확한 설명
- **완전성**: 필요한 모든 정보 포함
- **정확성**: 기술적 내용의 정확성
- **최신성**: 코드 및 정보의 최신 상태 유지
- **연결성**: 관련 문서들과의 유기적 연결
